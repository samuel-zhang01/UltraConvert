# Quality and estimate review — 2026-11-12

This is a scoped development update after 1.9.2, not a new published release.
All checks ran directly on the maintainer's Mac. Project CI and release Actions
remain disabled; no Actions run was dispatched.

## Findings and changes

| Finding | Resolution |
| --- | --- |
| Estimates counted files that the skip option would leave untouched. | Use only the files scheduled for conversion, explain skipped counts, and suppress estimates when the entire group is skipped. JPEG/JPG and MPEG/MPG aliases match the backend's behavior. |
| A size without a source comparison was hard to interpret. | Show the source size and an approximate smaller/larger comparison. Audio batches identify the total, and short-clip overhead is explained. |
| A changed quality or selection could leave an unclear estimate state. | Bind sampled results to the selection, target and quality; replace stale text with an explicit refresh prompt and **Estimate Again…**. |
| A longer result could push its button below the visible panel. | Put the action before the result, use the primary label color, and reveal both with a settled scroll position. Keep native controls and existing Reduce Motion behavior. |
| Sampling gave little feedback and validation started too late. | Report the sample scene, preserve cancellation feedback, validate duration/quality/source identity before sampling, and recheck source identity after sampling. |

The review used Apple's [slider guidance](https://developer.apple.com/design/human-interface-guidelines/sliders)
and [progress-indicator guidance](https://developer.apple.com/design/human-interface-guidelines/progress-indicators):
retain familiar native directions and values, show useful feedback, and do not
present an invented completion percentage for sampling work.

## Verification

- 26 Python compression tests passed, including real encoders, silent and misnamed
  videos, three-scene sampling, JSON/progress compatibility, invalid metadata,
  source replacement, cancellation and temporary-file cleanup.
- 132 native compression checks passed, including skip-aware totals, stale-result
  handling, unknown durations, repeated toggles, Reduce Motion, and complete
  estimate/action visibility at 760×570 and 880×750 in light and dark appearance.
- Native interface and getting-started suites passed.
- The maintained format and edge suites passed with zero failures, alongside
  18 security tests and 13 batch tests. Ruff lint/format and diff checks passed.
- Live review used an isolated app with separate preferences, empty rule storage,
  no Finder services and synthetic videos. MP4 and WebM estimates displayed both
  larger and smaller comparisons. Cancelling a 1080p sample restored the controls;
  a subsequent MP4 estimate succeeded. The review app was closed afterward.

## Limits and scope

A sampled video estimate remains approximate, especially for changing scenes.
Audio estimates do not guarantee container overhead or a final size. Image and
multi-video estimates remain outside this change. No new dependencies, background
polling, encoder profiles, rule formats or installation behavior were introduced.
The installed, signed 1.9.2 app remains the public release. Publishing another
release still requires the normal complete packaging, signing and release gates.
